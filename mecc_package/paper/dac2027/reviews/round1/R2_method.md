# R2 — Method and implementation consistency, round 1

Independent simulated review; I am not an actual DAC reviewer. Simulated scale: 1 reject, 2 weak reject, 3 borderline, 4 accept, 5 strong accept. This is not an official DAC rubric.

**Current-submission score: 1/5. Conditional technical score: 3/5.** I independently read the round1 manuscript, rendered PDF text, and assumptions file without reading other reviewers' reports. The conditional score assumes only displayed, nonwithdrawn targets become valid measurements. It does not grant feasibility, missing controls, external comparisons, or unreported synchronization tests.

The revision substantially improves scientific precision. Global request probabilities now have explicit layer weights; fixed capacities are distinguished from changing expert identities. The static proposition remains appropriately narrow. Planner tie breaking, termination, complexity, and rejection of infeasible minima are specified. The per-layer LRU equivalence now states serial execution, initialization, and admission restrictions. Overlap no longer presumes knowledge of future routes. Most importantly, Section IV acknowledges the prototype gaps and withdraws the incompatible full-mirror memory breakdown. Removing unsupported multi-GPU MECC points and reporting the two-GPU resident reference also improves the resource comparison.

These repairs improve the specification and honesty of the draft; they do not complete its implementation or supply evidence. The following issues still prevent an accept-level technical assessment.

1. **A feasible implementation remains unspecified.** Full mirroring is incompatible with the withdrawn example, but the replacement residency configuration or mirror-free execution path is absent. Reducing residency changes SSD traffic and potentially every plotted latency. Provide executable allocation constraints covering host residents, distinct mirrors, staging, transient copies, and GPU workspaces, plus enforcement and phase-aligned peaks. The conditional latency values cannot establish their own physical feasibility. The archived memory arrays remain in `assumptions.json`; mark them explicitly withdrawn there to avoid reuse.

2. **The planner is still a contract.** Synthetic layer exponents, optional co-occurrence ranking, missing feasibility enforcement, and profile provenance are acknowledged rather than reconciled. Freeze one implemented path with genuine profile-derived probabilities, actual per-layer capacities, deterministic rankings, and exact input revisions. Equation (3) is a coverage heuristic. Its “constant factors within a tier” explanation should not imply equivalence to minimizing Equation (2): extending HBM while preserving a CPU allocation can move both tier boundaries. Define that score operationally without suggesting a general latency gain formula. Prefill also fetches an expert once for multiple routed tokens; selection probabilities and object-fetch probabilities need separate definitions.

3. **Asynchronous correctness needs an executable schedule.** The readiness and lifetime conditions are sound, but the manuscript supplies no concrete mechanism for completion events, consumer protection, concurrent eviction, or temporary-buffer reuse. The admitted yield-before-synchronization risk cannot be resolved through wording. Provide pseudocode and GPU checks against the synchronous reference under repeated eviction and small buffers. Displayed deterministic quality checks, even if measured, cover their tested cases rather than all interleavings.

4. **The metric definition needs one final reconciliation.** Section II records residency when demand arrives; Section IV defines SSD demand-miss share using requests “served from SSD.” Prefetch can make these different. Define source-at-arrival counters independently of physical bytes and specify treatment of in-flight prefetch. Hold both byte traffic and admission fixed when attributing the overlap step to hidden transfer time; equal miss percentages alone are insufficient.

5. **The central technical hypothesis remains untested.** The revision correctly identifies the missing exclusive-LRU reference, fourth initialization/update cell, and controls separating capacities from initial identities. None is displayed, so none enters my conditional score. Cumulative ablation cannot establish the independent value of profile-derived planning beyond ordinary exclusive retention and shared transfer machinery. Exact baseline rules, cold-I/O semantics, calibration values, revisions, commands, and timing endpoints also remain necessary for reproduction.

The revised paper is a clearer research specification. Acceptance requires closing the admitted implementation gaps and measuring the newly focused finite-horizon hypothesis under enforced physical caps. Converting only the displayed scenario numbers into measurements would leave the technical case borderline.
