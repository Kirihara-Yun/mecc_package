# R22：以专家轨迹表示连续缓存更新

图 5 使用横向连续轨迹替代三行方框表格。四个时刻从左到右排列；每个专家保持独立颜色，专家的标识只在圆形节点中出现。上下两条浅色区域分别表示 HBM 与 CPU，每个区域的上、下位置分别表示 MRU、LRU。跨区曲线表示驻留集合与次序的变化，不表示额外的设备到主机拷贝。

读图顺序是初态、请求 a2、请求 a3、请求 a5。a2 在 HBM 内更新次序；a3 从 CPU 升入 HBM，a1 进入 CPU；a5 从 HDD 进入 HBM，a2 留在 CPU，a4 沿虚线离开 CPU 区域。末态仍为 HBM [a5,a3] / CPU [a2,a1]。a4 的出口与原轨迹相连，没有独立的右侧文字框。

颜色表示专家身份，区域表示所在层级，位置表示最近使用次序。轨迹与节点由 TRANSITION_AUDIT.json 的连续状态生成，端点逐项校验。字体继续使用与正文相同的 newtxtext/newtxmath；图为矢量 PDF，源文件为 method_redesign/residency_cases.tex。

本轮仅重绘图 5 并使图注与横向读图方向对应。其余十五幅嵌入图、现有数据数组及方法代码保持不变。图形单独渲染后再放回正文栏宽检查；版式和字体检查结果见 RECENCY_TRACK_VALIDATION.json。重建本轮可在上级目录运行 redraw_r22_recency_tracks.py，然后分别编译图和正文；已封存快照保持只读。
