# R16：三项动机与贡献对应

| Motivation | 贡献 | 机制 |
|---|---|---|
| 各层的专家访问分布不同，平均分配容量难以匹配需求 | Allocating capacity by layer | 比较各层下一未覆盖专家的需求，分配 HBM/CPU 槽位，并输出初始专家 ID |
| 专家从 GPU 淘汰后仍可能再次被访问 | Retaining experts after GPU eviction | 将 CPU 提升腾出的槽位用于保留 GPU 淘汰的专家，维护跨层级的最近访问顺序 |
| 运行任务选择的专家可能偏离离线画像 | Adapting residency to serving requests | 从画像初始化，依据真实请求接纳专家，在已编译容量内更新驻留集合 |

第三项描述现有按请求接纳与替换的适应作用，没有新增漂移检测器、在线重新编译或动态调整各层容量的声明。第二项解释权重如何跨层级保留；第三项解释驻留集合如何随请求更新。二者由同一运行期机制协同实现。

实验验证仍在 Evaluation 章节，不再单独充当第三项贡献。本轮仅修改引言的三个贡献条目；其余正文、图表与数据保持 R15 原样。
