## 3. 存储状态与共享部署

- **冷/暖 SSD 与 page cache**：主场景保持真实冷读；另做 warm 诊断并单列，记录 OS page-cache 和 store 语义。不能用 CPU 缓存的文件页当 SSD 带宽结果。
- **介质/带宽敏感性**：有第二块真实设备或可说明的受控限速时才执行；仿真/限速标明，不能冒充不同硬件实测。
- **共享服务器的任务内存限制**：固定并记录总任务 cap；镜像、pinned 和缓冲也受约束。可以测试受控 CPU 内存压力，但不能干扰他人任务。主结果保持可重复隔离条件。
- **能量/货币成本**：若正文要声称节能或省钱，单独测总能耗或给定可核验计价；否则只报 GPU 数、GPU-time 和 host/SSD 资源，不扩展解释。
- **并发服务**：如论文声称多请求 serving 优势，再加入并发度及 p50/p95/p99；否则 batch 敏感性不自动证明在线服务尾延迟。

这些是依赖资源或主张的扩展，不强迫目前单 A100 机器完成不存在的多卡或多介质实测。

## 5. 执行优先级与完成口径

**P0**：同步/异步正确性、真实字节 cap、分相位计量。未通过前，性能只作诊断。

**P1**：E01/E02、E04–E10、E13–E17、H01–H04；E03 在取得可用多卡资源后执行，资源缺口明确保留。

**P2**：E11/E12 完整扫描、跨硬件/介质、共享压力、采用后的 H05–H08、能量及在线并发。若对应内容进入摘要或贡献，相关 P2 升为必需证据。

每项状态使用 `planned / configured / running / failed / measured / audited / paper-integrated`，不能把 planned 或理想图计成完成。每项交付至少包含命令、配置与输入哈希、平台/时间、每次原值、计时窗、实际内存、失败记录和结论；完成后再登记真实 provenance。三次重复与配对种子各回答不同不确定性，不互相替代。
