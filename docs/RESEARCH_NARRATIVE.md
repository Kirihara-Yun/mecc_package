# 科研叙事总纲 —— 先有三级缓存模型，再有 MoE 实例

> 本文规定 MECC 对内研究与对外写作的统一故事。事实边界仍以
> [`APPLICABILITY.md`](./APPLICABILITY.md)、理论状态以 [`THEORY.md`](./THEORY.md)、
> 数字以 [`PROVENANCE.md`](./PROVENANCE.md) 为准。

## 1. 一句话定位

**MECC 是一个编译器引导的无损三级缓存架构：它面向工作集超过快层与中间层总容量、访问呈非均匀且可能漂移的只读大对象，在 HBM、CPU pinned memory 与 SSD 之间联合优化初始放置和在线迁移；MoE expert 推理是该抽象目前最重要、也最苛刻的实例化。**

MECC 这个名字保留了项目从 MoE 起步的历史，但研究贡献的逻辑顺序应当是：

$$
\text{三级异构缓存问题}
\rightarrow \text{概率模型与优化目标}
\rightarrow \text{编译期/运行期协同架构}
\rightarrow \text{MoE expert 映射}
\rightarrow \text{Mixtral 真机验证}.
$$

不能倒写成“为了处理 MoE expert 放置，我们拼接了若干缓存技巧”。

## 2. 第一性问题

考虑只读对象集合 $\mathcal D=\{1,\ldots,N\}$，对象 $i$ 的大小为 $s_i$，请求流为
$X_1,X_2,\ldots$。系统有三级介质 $\mathcal T=\{H,C,S\}$，满足容量序与延迟序

$$
B_H < B_C < B_S,\qquad T_H(s)\le T_C(s)\le T_S(s).
$$

放置变量 $x_{i,t}\in\{0,1\}$ 表示对象 $i$ 是否驻留于 tier $t$。静态问题可写为

$$
\min_x\quad \sum_{i=1}^{N}p_i\sum_{t\in\mathcal T}x_{i,t}T_t(s_i)
$$

subject to

$$
\sum_t x_{i,t}=1,\qquad
\sum_i s_i x_{i,t}\le B_t,\quad t\in\{H,C\}.
$$

这里 $p_i=\Pr[X=i]$ 是 profile 得到的访问概率。运行期进一步面对 $p_i$ 随时间变化，实际目标是最小化有限时域的暴露访问代价

$$
\min_{\pi}\quad
\mathbb E\!\left[\sum_{\tau=1}^{T}
T_{z_\tau}(s_{X_\tau})+M_\pi(\tau)\right],
$$

其中 $z_\tau$ 是请求命中的层级，$M_\pi$ 是策略 $\pi$ 引入的迁移、同步与替换开销。
这一定义解释了为什么“命中率更高”不自动等于“端到端更快”：迁移开销和计算重叠必须由真机实验裁决。

## 3. MECC 的解法

MECC 把上述随机优化拆成两个时间尺度：

1. **编译期先验优化。** 对代表性 trace 做 profile，以有界离散 Zipf 模型估计热度集中度；在当前“等大小对象、独立 tier 容量上限”实现中，按访问概率降序填满 HBM，再填满 CPU，剩余对象放 SSD。交换论证给出该静态排序的最优性（TH-004，`proven`）。
2. **运行期后验修正。** 真实请求偏离 profile 时，HBM 淘汰对象降级到 CPU，CPU 命中对象升级到 HBM，以联合动态 LRU 修正初始放置。它是一项在线启发式，不具有对任意 trace 优于静态拆分的普遍保证（TH-006，`refuted`）；优势必须写成带条件的经验结论。
3. **语义不变量。** 层级搬运是同精度恒等映射，不改变对象值。映射到 MoE 时即保持 fp16 expert 权重与原前向图不变（TH-008，`proven`）。

## 4. 为什么 MoE 是自然实例，而不是叙事起点

抽象量在 MoE 中有直接映射：

| 三级缓存抽象 | MoE 实例 |
|---|---|
| 只读大对象 $i$ | 单层单个 expert 权重块 |
| 请求 $X_\tau$ | router 对 expert 的一次选择 |
| 访问概率 $p_i$ | profile 后的 expert 路由频率 |
| 对象值不变 | fp16 权重逐值不变 |
| 慢层暴露代价 | SSD 冷读进入 token 生成关键路径 |
| 分布漂移 | prompt、任务或会话改变导致热点迁移 |

MoE 尤其合适，是因为它同时具备“大、稀疏激活、只读、访问偏斜、可观测路由”五个性质。
但当前证据只足以说“该架构在 MoE 上得到验证”，不能说它已在任意对象缓存、任意模型或任意 trace 上普遍有效。

## 5. 论文的专业叙事顺序

1. **问题**：总工作集超过 HBM+CPU，有一部分对象不可避免地落到 SSD。
2. **抽象**：定义对象、请求过程、三级成本、容量约束与迁移成本。
3. **静态模型**：Zipf/经验分布、期望访问成本、按秩放置和适用条件。
4. **动态模型**：profile 是先验，在线 trace 是后验观测；联合 LRU负责纠偏。
5. **实例化**：将对象与请求分别映射为 expert 权重和 router 选择。
6. **验证**：Mixtral 是当前 sub-CPU-memory 的 L2 主验证；DeepSeek 只是 CPU 可容纳对照。
7. **边界**：装得进 HBM 时无需缓存；装得进 CPU 时两级足够；动态策略无任意 trace 的支配性保证；跨应用普适性尚待实验。

## 6. 贡献应如何表述

- **架构贡献**：提出 profile-guided placement 与 online tier migration 协同的 HBM–CPU–SSD 三级缓存架构。
- **数学贡献**：给出三级期望访问成本模型；在等大小对象和独立容量约束下证明按概率排序、依次填满快层的最优性；证明恒等搬运的语义保持性。
- **系统贡献**：实现编译期 plan、运行期升降级、真实冷 SSD store 与统一端到端评测路径。
- **应用贡献**：将抽象实例化为无损 MoE expert 缓存，并在 Mixtral 的 SSD 强制场景中取得当前已核实的真机结果。

不要把“联合 LRU 对静态策略普遍更优”列为理论贡献；仓库中的最小反例已经否定这一表述。

## 7. 优点、短板与局限

**优点。** 问题抽象清晰；容量边界可判定；静态部分有可核验的优化模型；数值语义不依赖经验指标；编译期先验与运行期纠偏形成完整系统闭环。

**短板。** 当前静态最优性依赖等大小对象、独立容量上限与给定访问概率；在线策略缺少带分布条件的竞争比或期望 miss 界；端到端主证据只有一个大型 MoE；异步 I/O 与迁移成本尚未进入统一理论目标的可验证求解。

**正确的外推方式。** 可以提出对稀疏参数块、检索分片或只读模型组件的潜在适用性，但必须标为“由抽象推导出的候选方向”，不能写成已经验证的结论。

## 8. 禁止使用的叙事

- “MECC 为解决 MoE expert placement 增加了三级缓存、LRU、预取等若干优化。”
- “联合 LRU 总能覆盖更大的有效工作集，因此对任何 trace 更优。”
- “1.33× 相对有损 SwapMoE 且同时避免 36.12 PPL。”当前 36.12 的 baseline 身份未核实。
- “三级缓存对所有 MoE 都有效。”只有 expert 总量超过可用 CPU 内存、SSD 被迫进入关键路径时才有结构性价值。

推荐收束句：

> MECC 的核心不是某个 MoE 专用替换技巧，而是一个带静态先验、在线纠偏与语义不变量的三级缓存模型；MoE expert 推理把这一模型中的容量压力、访问稀疏性和慢层代价同时推到了足以被真机观测的程度。
